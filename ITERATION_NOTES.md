- **Gotchas:**
  - The loop gate is only `npm run typecheck && npm test` (unit); e2e is NOT auto-run by the gate. This session I re-used the already-running stack (:8002 Laravel + :3000 Nuxt with `TEST=1` + :3001 WS relay) and verified the suite by hand — e2e must be run separately.
  - In Playwright mobile emulation the LAYOUT viewport (`window.innerHeight` = 970) is taller than the visual viewport (844); `position: fixed; bottom: 0` resolves against the layout viewport → off-screen UI. Anchor mobile bars inside the app frame with `absolute` + a `relative` wrapper (and use `h-dvh`), not `fixed`.
  - `@nuxt/devtools`' floating widget intercepts pointer events at the bottom of the viewport during e2e; run the Nuxt dev server with `TEST=1` (see playwright.config.ts). `reuseExistingServer: true` means a stale manually-started server without `TEST=1` will be reused — restart it when devtools appears.
  - Gesture math must use stage-relative coords (via `toStagePoint`), not raw `clientX/clientY`, or pinch anchor drifts by the container's page offset.
  - `setViewportDirect` does NOT sync; call `setViewport` once on gesture end (kept — don't sync per-move or you spam the relay).
  - Konva bakes the viewport transform into the layer-canvas PIXELS (no CSS transform), so pan/zoom changes `canvasFingerprint`; the two-finger tests exploit pan-back-to-baseline to prove "no stroke committed".
  - A regression e2e that draws-then-gestures must use a PURE pan (both fingers translate by the SAME delta) so the inverse pan restores the exact viewport — a mixed pan+pinch changes zoom and the inverse translation won't land back on the baseline fingerprint.
- Konva 9.x has NO `globalAlpha` node property — a `globalAlpha` key in a shape config is silently ignored; only `opacity` is read (it sets `context.globalAlpha = getAbsoluteOpacity()`). Any transparency on Konva shapes must use `opacity`. (This is how highlighter strokes rendered opaque for so long.)
- To assert rendered translucency in e2e, sample the layer canvas pixel at the stroke midpoint (map CSS → canvas px via `canvas.width/rect.width`); the highlighter's black@0.5 over #f5f5f5 lands ~(122,122,122) vs the pen's opaque (0,0,0).
  - Pinch-zoom e2e: to get a deterministic target zoom, the finger DISTANCE ratio is what matters (zoom = currentDistance/startDistance against the fixed start). Start at ±60px and pinch OUT to ±120px = exactly 2×; the inverse returns to exactly 1.0×. The pinch must be pure (fixed centroid, fingers spread along the same axis) so the inverse gesture lands back on the baseline viewport/fingerprint.
  - In any stroke e2e that samples pixels, poll `canvasFingerprint` (≠ baseline) AFTER mouse-up/touch-up BEFORE calling `pixelAt` — sampling immediately can hit the background while the stroke still commits/renders.
  - A stale Nuxt dev server from a PREVIOUS session can still hold :3000; a freshly-started `npm run dev` then falls back to :3001, silently colliding with the WS relay — WS clients then hit the Nuxt fallback and live-sync e2e (remote preview) fails while everything else passes. Before relying on e2e live-sync, verify :3000 has the Nuxt process and :3001 only the ws-server (`ss -ltn`). Clean stray servers by PID (`kill`), not `pkill -f "nuxt dev"`/`pkill -f "server/ws-server.js"` — the pattern matches the invoking shell itself (AGENTS.md gotcha).
  - perfect-freehand `streamline`+`smoothing` shorten the rendered stroke TAIL (the end ~14px on a 200px stroke at these settings) while leaving the HEAD pinned to the first input point. Coordinate-probe assertions must anchor on the head (or stroke center), never the tail endpoint.

### What to verify (and fix if broken) with touch emulation
1. **Touch draw end-to-end**: on a mobile viewport with `hasTouch: true, isMobile: true`, a pen stroke (pointerdown → pointermove → pointerup with `pointerType: 'touch'`) must produce a rendered stroke element (same canvas-fingerprint / Konva-node assertion the collab spec uses).

5. Fix any breakage found with a regression test (unit and/or e2e). Do NOT break the existing mouse path (collab.spec must stay green).

### How to emulate touch in Playwright
- `test.use({ viewport: { width: 390, height: 844 }, hasTouch: true, isMobile: true })`.
- Playwright's `page.touchscreen.tap()` is limited; Konva relies on **Pointer Events**, so the most reliable simulation is dispatching real pointer events with `pointerType: 'touch'` on the stage root, e.g. `page.locator('.whiteboard-container').dispatchEvent('pointerdown', { pointerId: 1, pointerType: 'touch', clientX, clientY, isPrimary: true, pressure: 0.5 })` followed by pointermove/pointerup with `pointerId` held constant. Multi-touch = two `pointerId`s (pointerId 1 + 2) for the pinch/pan gesture.
- Reuse the existing fingerprint helper approach from `collab.spec.ts` to assert a stroke rendered (getImageData-based, since headless Chromium serves a stale surface to drawImage).
